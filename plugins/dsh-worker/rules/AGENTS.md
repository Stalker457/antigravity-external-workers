## DeepSeek Harness（DSH）协同模式专属规范（仅在启用 DeepSeek / DSH 时生效）
- **严格作用域边界**：本节规范**仅当用户在对话中明确要求使用 DeepSeek / DSH / DeepSeek CLI（`dsh-worker`）协同执行时**才启动（若用户只说“用 DeepSeek”而未指定 OpenCode，默认走 DSH）；**用户未提及使用 DeepSeek / DSH，或明确指定使用 OpenCode 的其他对话完全不启用本节限制**，按各对话自身策略正常执行。
- **主模型职责与额度保护**：在启用 DSH 协同的对话中，主模型只负责**深度思考、架构分析、规划方案与最终验收**，严禁亲自连续调用 `read_file` / `Select-String` 去翻阅大型源码或干检索苦力杂活（单轮只读检查控制在 2～3 次调用内，验收合并为 1 条命令）；所有繁重的源码排查、代码编写、测试与修复一律写进任务书交由 DSH Worker（`run_dsh_worker.py`）执行。
- **多路并行拆单优先**：在启用 DSH 协同且任务可拆分为互不冲突的独立模块、文件或只读调研视角时，主模型应在规划阶段**主动提出多路并行拆单方案**（单轮并发上限 **6 路**），明确各子任务的文件写入隔离边界；确认后使用同一 `--batch-id` 与 `--batch-title` 后台并发派发（在 `DSH Monitor` 中归为同一任务组按标签页切换），全部完成后统一验收。
- **执行模式自动选型（`native` vs `ptc`）**：
  - **简单/单点任务**（修改 1～2 个文件、单步问答或小型脚本）默认走 `native` 模式（不加 `--ptc`）。
  - **复杂任务**（多文件改动、重构、跨模块排查或需要多步工具探索）务必为 `run_dsh_worker.py` 传入 `--mode ptc`（或 `--ptc`，内部会在 `--profile headless` 之前自动加载 `~/.dsh/patches/ptc.yml`），并在任务规划阶段写明每个子任务的执行模式；若用户明确指定 `ptc` 或 `native`，按用户要求执行。
